# API Documentation

:::warning API v1 is turned off

The legacy **v1 API has been completely turned off as of July 7, 2026**. Please migrate to the **v2 API** documented below. See the [API v1 Brownouts blog post](/blog/api-v1-brownouts) for details.

:::

Sourcify has two APIs:

- [Server API](#server-api-documentation): The main API for Sourcify, used to verify contracts and get information about verified contracts under `https://sourcify.dev/server`.
- [4byte (Signature) Service API](#4byte-signature-service-api-documentation): The API for the 4byte signature service to query and submit Ethereum function, event, and error signatures under `https://api.4byte.sourcify.dev`.

:::tip 🤖 AI Agents
If you are an LLM or an AI agent, check out the machine readable specs:

- [OpenAPI JSON spec for Sourcify Server API Documentation ](https://sourcify.dev/server/api-docs/swagger.json)
- [OpenAPI JSON spec for 4byte (Signature) Service API Documentation](https://api.4byte.sourcify.dev/api-docs/swagger.json)
  :::

## Basic usage

### Verification

The main Sourcify API for verification is `/v2/verify/{chainId}/{address}`, it either returns a a ticket with a `verificationId` or an error.

The status of the verification process can be tracked by `/v2/verify/${verificationId}`. For additional details, please check the [documentation below](#server-api-documentation).

<Tabs>
    <TabItem value="curl" label="curl">
        ```bash
        verification_result=$(
          curl -sS -X POST \
            'https://sourcify.dev/server/v2/verify/11155111/0x2738d13E81e30bC615766A0410e7cF199FD59A83' \
            -H 'Content-Type: application/json' \
            --data-raw '{"stdJsonInput":{"language":"Solidity","sources":{"contracts/Storage.sol":{"content":"// SPDX-License-Identifier: MIT\npragma solidity ^0.8.0;\n\ncontract Storage {\n    uint256 number;\n\n    function setNumber(uint256 newNumber) public {\n        number = newNumber;\n    }\n\n    function getNumber() public view returns (uint256) {\n        return number;\n    }\n}\n"}},"settings":{"optimizer":{"enabled":false,"runs":200}}},"compilerVersion":"0.8.7+commit.e28d00a7","contractIdentifier":"contracts/Storage.sol:Storage","creationTransactionHash":"0xb6ee9d528b336942dd70d3b41e2811be10a473776352009fd73f85604f5ed206"}'
        )

        verification_id=$(echo "$verification_result" | jq -r '.verificationId // empty')

        if [ -n "$verification_id" ]; then
          curl -sS \
            "https://sourcify.dev/server/v2/verify/${verification_id}"
        else
          echo "$verification_result"
        fi
        ```
    </TabItem>

### Contract Lookup

Verified contracts data can be fetched using the `/v2/contract/{chainId}/{address}?fields=all` API. For the full list of fields and additional parameters please check the [documentation below](#server-api-documentation).

Contract data can also be viewed in the web application at [https://repo.sourcify.dev/11155111/0x2738d13E81e30bC615766A0410e7cF199FD59A83](https://repo.sourcify.dev/11155111/0x2738d13E81e30bC615766A0410e7cF199FD59A83). This URL is intended only for browsing contract data through the UI.

<Tabs>
    <TabItem value="curl" label="curl">
        ```bash
        curl -sS \
          'https://sourcify.dev/server/v2/contract/11155111/0x2738d13E81e30bC615766A0410e7cF199FD59A83?fields=all'
        ```
    </TabItem>

    <TabItem value="js" label="Javascript">

        ```js
            "https://sourcify.dev/server/v2/contract/11155111/0x2738d13E81e30bC615766A0410e7cF199FD59A83?fields=all"
        );

        const contract = await response.json();
        console.log(contract);
        ```

### Contract Deletion

The deployer of a verified contract can ask Sourcify to delete the verification data of the contract, source code included. A Sourcify maintainer approves or rejects each request, so a deletion is not immediate.

The deployer is the account that Sourcify has as the deployer of the contract: the sender of the transaction that created it, also if a factory created it. You can read it with `/v2/contract/{chainId}/{address}?fields=deployment`. If Sourcify has no deployer for your contract, or you cannot sign with the deployer account, write to [hello@sourcify.dev](mailto:hello@sourcify.dev).

**1. Sign this message** with the deployer account (`personal_sign`, EIP-191). Lines end with one line feed, and the last line has no line end:

```text
Sourcify contract deletion request

I am the deployer of the contracts below. I ask Sourcify to delete their verification data, source code included.

Service: sourcify-contract-deletion
Version: 3
Issued at: 2026-01-31T12:00:00Z
Contracts (2):
1:0xae519fc2ba8e6ffe6473195c092bf1bae986ff90
10:0x73b647cba2fe75ba05b8e12ef8f8d6327d6367bf
```

- One line `chainId:address` for each contract, sorted by chain id, then by address. Addresses are in lower case.
- `Issued at` is the current UTC time without milliseconds. The request must arrive not later than 15 minutes after it.
- A request has at most 50 contracts. All of them must have the signer as the deployer.

**2. Send the request** to `POST /delete` with the same contracts and time, and the signature:

```bash
curl -sS -X POST 'https://sourcify.dev/server/delete' \
  -H 'Content-Type: application/json' \
  --data-raw '{"contracts":[{"chainId":1,"address":"0xae519fc2ba8e6ffe6473195c092bf1bae986ff90"},{"chainId":10,"address":"0x73b647cba2fe75ba05b8e12ef8f8d6327d6367bf"}],"issuedAt":"2026-01-31T12:00:00Z","signature":"0x..."}'
```

The answer has status `202` and a request id: `{"requestId":"...","state":"pending"}`. An error answer has the form `{"error":"<code>","message":"<text>"}`. The most frequent codes are `not_deployer` (403: the signer is not the deployer that Sourcify has), `not_verified` (422), `request_expired` (400), and `request_pending` (409: the deployer has a request that is not finished).

**3. Read the state** with `GET /delete/{requestId}`:

```bash
curl -sS 'https://sourcify.dev/server/delete/<requestId>'
```

The `state` is `pending`, `done`, `rejected`, `expired`, or `failed`. A request that no maintainer handles in 14 days expires.

After a deletion, source files that other verified contracts also use stay in Sourcify with those contracts. The deletion does not stop a new verification of the same contract.
